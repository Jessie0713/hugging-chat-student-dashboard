# HuggingChat 學習儀表板：功能與使用說明

本文整理本系統（huggingchat-dashboard）的定位、角色、頁面功能與操作流程，供論文方法／系統說明章節使用。內容以目前程式與課程規則為準；儀表板分數為**初步成績**，最終仍由教師依練習狀況判定。

---

## 1. 系統定位

本系統是英語口說課的**學習儀表板**，不是聊天室本體。

| 系統 | 角色 |
| --- | --- |
| 主系統（Chat UI） | 學生用語音與 AI 情境對話、完成有效對話、接受 CEFR 評級、領獎章 |
| 本儀表板 | 彙整對話與進度、視覺化指標、練習建議（SRL：觀察→策劃→行動）、初步計分、教師名冊與切題審查、規則問答助手 |

學生在主系統練口說；儀表板負責**看自己練得怎樣、下一步練什麼、成績怎麼來**。打開儀表板頁面、與助手聊天、按讚／回饋，**都不算**有效口說，也**不算**「查看儀表板」計次。

---

## 2. 系統架構（簡述）

| 層 | 技術 | 本機啟動 |
| --- | --- | --- |
| 前端 | React + Vite + MUI | `cd frontend && npm run dev`（埠 **5174**） |
| 後端 | FastAPI + Uvicorn | `cd backend && source .venv/bin/activate && uvicorn main:app --reload --host 0.0.0.0 --port 8000` |
| 學生／教師資料 | MongoDB（Motor），分兩套庫 | `.env` 的 `ROLLING_LEVEL_MONGO_*`、`FIXED_LEVEL_MONGO_*` |
| 姓名等課務 | Moodle MySQL（可選，SSH tunnel） | `.env` 的 `SSH*`／`DB_*_API` |
| 生成式 AI | Azure OpenAI | 對話分析「語法健檢」、助手回答；未設定時分析會回固定說明 |

前端開發網址：`http://localhost:5174`。API 以 `/api` 代理到後端 8000。

兩套評級資料**不可混用**：

| 分流 `source` | 畫面名稱 | 評級邏輯（論文／教師用） |
| --- | --- | --- |
| `rolling_level` | 變動等級 | 依對話動態評 CEFR（`users.agentCefr`） |
| `fixed_level` | 固定等級 | 進房先選目標練習等級；適配看評估大階是否達到所選等級 |

學生端**不解釋**實驗組／對照組或兩套系統名稱；學生只用自己收到的連結。

## 3. 誰用、怎麼進去

首頁 `/` 可選分流後進入。正式課程通常直接發儀表板網址，不必經首頁。

### 3.1 學生

網址格式：

```text
/{source}/student/{hfUserId}/overview
```

例：`/rolling_level/student/2481643/overview`

- `source`：`rolling_level` 或 `fixed_level`
- `hfUserId`：主系統使用者識別（網址參數，**不是**正式帳密登入）
- 進入後上方導覽：**總覽**、**對話分析**、**練習建議**
- 右下角手電筒按鈕：打開「恐龍學習助手」

### 3.2 教師

首頁選「教師儀表板」，輸入教師代碼（預設環境變數／前端常數，非正式個人帳號），進入：

```text
/teacher/{source}
```

可切換：變動等級、固定等級、兩組合計。右下角為「班級助教」（知識圖譜，與學生 FAQ 分開）。

### 3.3 管理者

首頁選「管理者」，帳號由伺服器初始化（`backend/scripts/init_admin.py`），不可自行註冊。進入 `/admin`：學生 FAQ、教師圖譜、問題回報。

## 4. 課程規則（成績與練習的共同前提）

### 4.1 指定主題（白名單 8 題）

課程成績與獎章里程碑只認這 8 個指定練習主題。其他聊天室不算課程題。學生問「有效主題是哪幾個」時，**把 8 個主題全部告訴學生**。每練習兩個主題，到 eeclass 填問卷。

系統白名單（assistant）：

1. Product Design Talk  
2. Biomimicry Explainer  
3. Handmade vs Machine Debate  
4. Can Machines Think?  
5. VR Treatment Talk  
6. EQ vs IQ Compare  
7. Panama Canal Story  
8. Future Movement Planner  

### 4.2 有效對話

以**指定主題**為單位，不是整學期一次。

- 每個指定主題至少 **8 次**有效回應  
- 必須**語音輸入**、內容**全英文**  
- 每次至少 **2 句英文**，或單句超過 **10 個字**  
- 符合標準的句子旁有**黃色麥克風**  
- 該主題側邊欄變**綠色**、旁邊有**黃點**：此主題已符合標準  

沒有語音、非英文、次數不夠：不列入該主題有效對話。

### 4.3 練習大階（CEFR）

| 大階 | CEFR |
| --- | --- |
| 入門 | PreA1 |
| 基礎 | A1、A2、**B1** |
| **進階** | **B2** |
| 高階 | C1、C2、C1C2 |

**B1＝基礎，不是進階。進階＝B2。** 固定等級若學生選「進階」，評估達進階或高階都算適配符合。

### 4.4 獎章與成績為什麼不同

- **獎章**：主系統條件達成即發放，**不因切題審查收回**。  
- **成績**：還要看這次對話有沒有在練該主題。切題（onTopic）或有碰邊（related）才計分；亂聊、無關（offTopic）該題沒有分數。因此獎章看起來過了、成績可以比較低。  
- 儀表板分數是初步計算，老師之後仍會判定。學生看總覽「成績」分頁。

切題三級：onTopic 計分；related 仍計分；offTopic 不計該題，請到主系統重開房間。不因缺少指定關鍵字就判不切題。

### 4.5 初步成績公式（最高 108）

由既有計分服務計算，**不可由語言模型自行改分**。

\[
108 = 里程碑\ 80 + 守護龍\ 20 + 額外加成\ 8
\]

基本要求：至少完成 **8** 個指定主題的有效練習。

**里程碑**（主題數 **且**「查看儀表板」次數都要到）：

| 完成指定主題 | 查看儀表板次數 | 分數 |
| ---: | ---: | ---: |
| 2 | 2 | 30 |
| 4 | 3 | 50 |
| 6 | 4 | 60 |
| 8 | 5 | 80 |

**守護龍**：5 個主題的**第二次** CEFR 評級達進階（B2+）→ 20 分。與「練習建議達標」（5 個不同主題達到進階＋有效對話）是分開的條件。

**額外加成**上限 8：查看儀表板超過 5 次，多一次加 2 分（與超過 5 題守護龍的加分合計不超過 8）。

### 4.6 什麼叫「查看儀表板」（計次）

**算：** 走完練習建議（觀察 → 策劃勾目標 → 開始練習）並到**主聊天室開始練習**。系統記 48 小時內 `practice_room_pick` 與 `practice_room_enter` 配對。

**不算：** 只開總覽、只問助手、點讚、回饋、單純瀏覽頁面。

## 5. 學生儀表板：頁面與使用方式

### 5.1 總覽 `.../overview`

用途：一次看到語言表現、等級／情境進度、獎章與初步成績、自己的練習紀錄。

常見區塊：

- **語言指標**：英文佔比、詞彙豐富度、平均輪次、平均時長（只算學生發言；英文佔比＝英文字母／（英文字母＋漢字））  
- **學習趨勢**：可切語言／豐富／互動／時長  
- **等級分佈**（變動等級）或情境等級（固定等級）  
- **徽章總覽**：已獲得／未獲得；「成績」分頁看切題後初步成績與主題進度  
- **整體等級趨勢**（變動等級）：可看 Daily／Raw、篩單一情境  
- **我的練習**：近期對話與切題狀態  

使用建議：先看總覽知自己程度與還缺哪些已公布主題，再去練習建議選下一間房；要對成績細節則開「成績」分頁，不要以為獎章分數等於課程成績。

### 5.2 對話分析 `.../conversations`

用途：回看聊天紀錄，並用 AI 產出可執行的練習建議。

- 左側／列表：對話紀錄（可分頁展開）  
- **AI 語法健檢報告**：依學生整體英文對話分析弱點，對照培力英檢口說需要的能力給建議與短期練習方向（**不保證通過考試**）  
- 可搭配情境使用次數等摘要  

使用方式：點「AI 語法健檢報告」→ 依報告決定下次要練的句型／任務 → 再到練習建議選房並回主系統開口說。培力英檢怎麼規劃練習，也引導到這一頁的報告，而不是只走練習建議流程。

### 5.3 練習建議 `.../practice-next`（觀察 → 策劃 → 行動）

對應 SRL：先看自己、再設目標、再去練。走完並進入主聊天室，才計「查看儀表板」。

| 步驟 | 學生做什麼 |
| --- | --- |
| **觀察** | 看目前程度、弱點、與「進階（B2）＋有效對話」的距離 |
| **策劃** | 勾選想加強的焦點（focus）；系統依弱點與模式規則最多推薦 **2** 間聊天室（同主題只留 1） |
| **開始練習** | 點選推薦房間，跳轉主系統開始語音練習 |

目標（程式常數）：**5** 個不同課程主題達到**進階**且完成**有效對話**。固定等級還須在主系統**選進階**。走完流程**不等於**已經達進階。

推薦排序大意（細節見 `docs/練習建議推薦機制.md`）：

- **固定等級**：已選進階且評估已達進階、只差有效對話 → 最優先；已算進進度的排最後  
- **變動等級**：評估已達進階、只差有效對話 → 最優先；已完成的排最後  

### 5.4 恐龍學習助手（右下手電筒）

用途：用繁中回答**課程規則與練習方式**（FAQ／知識庫），可依回答出現「總覽／練習建議／對話分析／主系統」捷徑。

- 快捷問題例：成績怎麼算、有效對話、進階＝B2、練習建議怎麼達標、培力英檢、獎章與成績為何不同  
- **不能**改成績、發獎章、改權限  
- 問答與點讚**不加分**  
- 未驗證時只能公共 FAQ；個人進度需要主系統可驗證登入（網址學號不能當正式認證）  
- 按讚／倒讚：按過變實心，同一則只能改選另一邊；資料庫同一則回覆只留最新一筆投票  

學生頁即使瀏覽器還留著教師／管理者登入，快捷問題仍應是**學生 FAQ**，不會變成「這一班進度如何」。

## 6. 教師儀表板：功能與使用方式

進入後可切 **變動等級／固定等級／兩組合計**。兩組是不同 Mongo、不同評級與切題房間定義，名冊與圖表不可混成同一套篩選。

### 6.1 班級 KPI 與圖表

上方可見平均成績、完成主題、二次進階、英文佔比、總對話數等。兩組合計時，用等級／成績分布／學習趨勢**比較兩組**，不要用單一組的等級 KPI 去篩另一組學生。

### 6.2 名冊

每位學生列：姓名、email、組別（兩組合計時）、等級、總分、對話數、英文佔比、詞彙、輪次、時長、有效主題數／8、查看儀表板次數、二次進階／5。可搜尋、連到該生總覽或對話分析、看獎章、點「成績」做切題審查。

未達標通常指：白名單主題尚未完成有效對話，或練習建議的 5 題進階＋有效對話還沒到。

### 6.3 切題審查

在名冊點該生「成績」才計算切題。onTopic 與 related 都計分；offTopic 不計該題。助手不會在一般聊天裡暗中重算。

### 6.4 班級助教

用**教師知識圖譜**（節點＋關係，存在 Mongo，管理者可編）說明進度、未達標、切題與獎章差異。回答去識別（如 student-1），不把單一學生完整對話給其他學生。不要叫教師去學生練習建議頁練口說。

## 7. 管理者後台（營運，非學生實驗介面）

`/admin` 分頁籤：

| 頁籤 | 做什麼 |
| --- | --- |
| 學生 FAQ | 看／改問答與其他說明檔，存 Mongo；恐龍助手讀這份 |
| 教師圖譜 | 看／改節點與關係，存 Mongo；班級助教讀這份 |
| 問題回報 | 助手讚／倒讚／文字回報（只讀檢視） |

知識圖譜與 FAQ 本體可在網頁編輯並寫入 Mongo；改完儲存，對應助手下次回答就會用新內容（檔案只當種子）。

## 8. 建議的學生操作流程（論文可當「使用程序」）

```text
主系統語音練習（指定主題）
    → 儀表板總覽：看程度、獎章、初步成績
    → 對話分析：產出 AI 語法健檢報告（含培力英檢相關建議）
    → 練習建議：觀察弱點 → 勾目標 → 開始練習
    → 進入主聊天室繼續開口
    → 每兩個主題至 eeclass 填問卷
```

計分相關提醒寫進論文時建議同時註明：

1. 「查看儀表板」＝練習建議流程＋進入主聊天室，不是 page view。  
2. 助手與總覽瀏覽不加分。  
3. 儀表板 108 分為初步成績，教師仍會判定；切題後成績可以低於獎章。

## 9. 本機開發啟動（複製品時）

環境變數放在**專案根目錄** `.env`（後端固定讀根目錄，不讀 `backend/.env`）。

```bash
# 終端機 1：後端
cd backend
source .venv/bin/activate
uvicorn main:app --reload --host 0.0.0.0 --port 8000

# 終端機 2：前端（建議 Node 22.23.4 以上，與學校資安 22 線一致）
source "$HOME/.nvm/nvm.sh"
cd frontend
npm run dev
```

瀏覽器：`http://localhost:5174`。Mongo 須依 `.env` 的 URI 可連線（常見為 tunnel 埠，不是本機預設 27017）。

## 11. 寫論文時建議區分的層次

1. **主系統（口說練習）** vs **儀表板（後設認知與回饋）**  
2. **獎章（解鎖條件）** vs **成績（切題後計分）** vs **教師最終判定**  
3. **練習建議達標（5 主題進階＋有效對話）** vs **守護龍（第二次評級 B2+）** vs **里程碑 80 分（8 主題＋儀表板配對次數）**  
4. **學生可見介面**（不呈現 rolling／fixed 名稱）vs **教師／研究者可見的兩組設計**
